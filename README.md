# Домашний кинотеатр

Минимальный «онлайн-кинотеатр» для личной коллекции видео на USB-диске.

- **Сервер** (`server.js`, Node.js + Express): сканирует папку, отдаёт список видео,
  стримит файлы с поддержкой HTTP Range (перемотка работает), конвертирует `.srt` → WebVTT
  (включая файлы в cp1251), вход по паролю (подписанная HttpOnly-cookie, защита от перебора).
- **UI** (`web/`, React + Vite): библиотека по папкам, поиск, «Продолжить просмотр»,
  плеер с субтитрами, автопереход к следующей серии. Прогресс хранится в браузере.

Без транскодирования — браузер получает файл как есть (у Pi 5 нет аппаратного кодировщика).

## Воспроизведение и перекодирование

Для каждого файла сервер через `ffprobe` смотрит кодеки и выбирает режим (он виден в плеере):

| Режим | Когда | Нагрузка на Pi 5 |
|---|---|---|
| **оригинал** | MP4/WebM с H.264 + AAC/MP3 | нет, файл отдаётся как есть |
| **перекодирование звука** | MKV/AVI/MP4 с H.264, если файл нельзя отдать как есть (контейнер, AC3/E-AC3/DTS, не первая дорожка) | ~10–20% одного ядра |
| **перекодирование видео** | Xvid/DivX (MPEG-4), HEVC, 10-bit и т.п. | высокая: SD — легко, 1080p — на пределе |

В режимах с ffmpeg поток идёт как фрагментированный MP4; перемотка перезапускает ffmpeg с нужной секунды,
поэтому у плеера своя шкала. Когда видео копируется, поток может начаться только с ключевого кадра — сервер
находит его заранее (`/api/seekpoint`), и шкала с субтитрами показывают точное время. Звук в режимах с ffmpeg
всегда перекодируется в AAC с выравниванием по меткам времени (`aresample=async`), чтобы не было рассинхрона
на файлах с кривыми таймстемпами (AVI с VBR MP3, TV-рипы с пропусками). Можно выбрать звуковую дорожку и субтитры — внешние `.srt`/`.vtt` рядом с файлом
и встроенные текстовые (SRT/ASS) из MKV. Встроенные субтитры при первом выборе извлекаются из файла целиком
(для большого MKV на USB-диске это до минуты), потом берутся из кеша `CACHE_DIR`.
Выбор языка звука и субтитров запоминается для следующих серий.

Нужен ffmpeg: `sudo apt install ffmpeg`.

Одновременных потоков через ffmpeg — отдельно по «тяжести»: `MAX_AUDIO_TRANSCODES` (видео копируется,
перекодируется только звук; по умолчанию 6) и `MAX_VIDEO_TRANSCODES` (перекодирование видео; по умолчанию 2,
старое `MAX_TRANSCODES` тоже понимается). Перемотка не занимает второй слот: прежний поток зрителя закрывается сразу.
Если слоты заняты, плеер так и пишет. Текущая загрузка: `GET /api/status`.

Ограничения: у Pi 5 нет аппаратного кодировщика, перекодирование видео — программное (libx264).
На iPhone/Safari режимы с ffmpeg могут не работать (Safari требует Range-запросы); Android и десктопные браузеры — ок.

Субтитры: положите рядом `Фильм.srt` или `Фильм.ru.srt`, `Фильм.en.srt` — подхватятся автоматически.

## Музыка

Если задан `MUSIC_ROOT`, появляется вкладка «Музыка»: дерево папок, альбом с обложкой и треками из тегов,
мини-плеер внизу экрана (играет, пока листаете библиотеку и переключаетесь на «Кино»; ставится на паузу
при запуске видео), очередь из альбома, перемешивание, управление с экрана блокировки (Media Session).

| Источник | «Оригинал» | «Экономно» |
|---|---|---|
| MP3, OGG/Opus | как есть | как есть |
| FLAC, WAV | как есть | AAC `MUSIC_ECO_BITRATE` |
| APE, WavPack, AIFF, TTA | → FLAC (без потерь) | AAC |
| WMA, M4A, MPC | → AAC | AAC |
| Трек из CUE-образа | вырезается → FLAC | вырезается → AAC |

CUE-образы (один FLAC/APE на альбом + `.cue`) показываются как отдельные треки; `.cue` в cp1251 и ссылки на `.wav`
вместо реального `.flac`/`.ape` поддерживаются. Перекодированные треки кладутся в `CACHE_DIR/audio`
(до `MUSIC_CACHE_MB`, старые удаляются), следующий трек очереди готовится заранее.
Обложка: `cover/folder/front.*` в папке альбома, в подпапке `Covers/Scans`, в родительской папке (CD1/CD2)
или встроенная в первый трек.

По умолчанию в домашней сети выбирается «Оригинал», снаружи — «Экономно»; переключается в мини-плеере.

## Плейлисты

Вкладка «Плейлисты» (рядом с «Кино» и «Музыкой», если задан `MUSIC_ROOT`):

- список плейлистов: ▶ — играть, ✎ — редактировать, 🗑 — удалить (с подтверждением); нажатие на название раскрывает
  треки, трек запускает плейлист с этого места;
- «+ новый» — создать и сразу перейти к выбору треков;
- редактор: название меняется в заголовке, всё сохраняется автоматически;
  - **Состав** — дерево папок с музыкой и поиском; флажок у каждого трека и «Все треки папки»
    (треки из CUE-образов тоже выбираются по одному); **«+»** на папке добавляет все треки этой папки
    и всех подпапок в порядке дерева, без повторов (рядом коротко видно, сколько добавлено);
  - **Порядок** — перетаскивание за ⠿ мышью и пальцем (у краёв экрана страница прокручивается),
    ✕ убирает трек; с клавиатуры — стрелки на ручке.

Хранятся в `DATA_DIR/playlists.json` (по умолчанию `data/` в папке приложения; папка в `.gitignore`,
`deploy.sh` её не трогает). Запись атомарная; если файл повреждён, он переименовывается в `playlists.json.broken-…`.
Треки, чьих файлов больше нет на диске, показываются серыми и пропускаются при воспроизведении.

## Кеш

`CACHE_DIR` (по умолчанию `cache/` в папке приложения, на SSD):

| Папка | Что | Очистка |
|---|---|---|
| `audio/` | CUE-треки и перекодированный звук | сразу после каждого перекодирования — не больше `MUSIC_CACHE_MB`, удаляются самые давно использованные |
| `covers/` | уменьшенные обложки | раз в сутки |
| `subs/` | встроенные субтитры, извлечённые из MKV | раз в сутки |

Раз в сутки (и через минуту после старта) во всех папках удаляются файлы, к которым не обращались
`CACHE_MAX_AGE_DAYS` дней (по умолчанию 90), и недописанные `.tmp` от прерванных перекодирований.
Каждое обращение к файлу в кеше обновляет его время — так считается «последнее использование».

## Версии

Версия — в `package.json` (видна в `/health`, `/metrics` и в сообщении о старте вместе с коммитом).
Поднимается в каждом изменении: новая функция — `1.x.0`, исправление — `1.x.y`.

## Установка на mediaserver

Нужен Node.js 18+. Выполнять по одной команде:

1. Скопировать проект в `/opt/home-cinema` (например, `scp -r home-cinema pi@mediaserver:/tmp/` и затем `sudo mv /tmp/home-cinema /opt/`).
2. `cd /opt/home-cinema`
3. `npm install`
4. `npm run build`
5. `cp .env.example .env` и отредактировать: `MEDIA_ROOT`, `CINEMA_PASSWORD`, `CINEMA_SECRET` (`openssl rand -hex 32`).
6. Проверка вручную: `set -a; . ./.env; set +a; node server.js` → открыть `http://192.168.50.5:8090`.
7. `sudo cp deploy/home-cinema.service /etc/systemd/system/` (поправьте `User=` при необходимости).
8. `sudo systemctl enable --now home-cinema`

## Обновление и автодеплой

Каждый merge в `main` автоматически выкатывается на mediaserver: `.github/workflows/deploy.yml` запускается
на self-hosted runner'е на самом Pi и вызывает `deploy.sh`. Тот же скрипт можно запустить руками:

```bash
/srv/storage/apps/streamserver/deploy.sh
```

`deploy.sh`: `git pull --ff-only` → `npm ci`, если менялись зависимости → сборка UI во временную папку
и подмена (неудачная сборка не ломает работающий UI) → `sudo systemctl restart streamserver` → проверка `/health`.
Если `/health` отвечает 503 (например, не смонтирован USB-диск), деплой проходит с предупреждением;
если служба не ответила за 30 с — деплой падает и показывает журнал. Вручную деплой запускается и из вкладки
Actions (`workflow_dispatch`).

### Установка runner'а (один раз)

Runner регистрируется на этот репозиторий отдельно от runner'ов rag-server и бота.
GitHub → Settings → Actions → Runners → New self-hosted runner → Linux / ARM64 — там же актуальные команды
скачивания и токен. На mediaserver:

```bash
mkdir -p /srv/storage/apps/actions-runner-streamserver && cd /srv/storage/apps/actions-runner-streamserver
# скачать и распаковать архив runner'а (команды со страницы GitHub), затем:
./config.sh --url https://github.com/codebrujo/streamserver --token <ТОКЕН> \
  --name mediaserver-streamserver --labels streamserver --unattended
sudo ./svc.sh install pi && sudo ./svc.sh start
```

Runner работает от `pi`, которому нужно право только на перезапуск службы:

```text
# /etc/sudoers.d/streamserver-deploy
pi ALL=(root) NOPASSWD: /usr/bin/systemctl restart streamserver
```

⚠️ Репозиторий публичный. Чтобы чужой PR из форка не мог запустить свой workflow на runner'е в домашней сети:
Settings → Actions → General → «Approval for running fork pull request workflows» →
**Require approval for all external contributors**. Сам `deploy.yml` срабатывает только на push в `main`
этого репозитория.

## Уведомление о старте

При каждом запуске (в том числе после автодеплоя) сервер пишет в служебный канал chatguru —
так же, как rag-server и aikrishna:

> Streamserver started and is listening on 0.0.0.0:8090, version 1.0.0 (3f2a1bc), videos: 628, music folders: 412

Сообщение отправляется только после завершения сканирования видео и музыки (сколько бы оно ни длилось),
до 3 попыток (сразу, через 15 с и через минуту); причина неудачи пишется в журнал.
Если что-то не так (не смонтирован диск, нет ffmpeg), в конце добавляется `problems: …`.
Настройки — `CHATGURU_URL`, `CHATGURU_TOKEN`, `CHATGURU_APP_TOKEN`, `CHATGURU_SERVICE_CHANNEL` (по умолчанию `ito`),
те же значения, что в `.env` rag-server. Без `CHATGURU_URL` уведомление просто пропускается.

## Мониторинг

Без логина, для monitoring-mcp-bot и Prometheus:

- `GET /health` — `200 {"status":"ok", …}` или `503 {"status":"degraded","problems":[…]}`, если недоступна папка
  с видео/музыкой (USB-диск отвалился) или нет ffmpeg. Подробности (версия, число видео, загрузка перекодирования)
  отдаются только прямым запросам из LAN; через nginx на EC2 — только `status`.
- `GET /metrics` — формат Prometheus, только из LAN (через прокси — 404):
  `streamserver_up`, `streamserver_info{version,commit}`, `streamserver_uptime_seconds`,
  `streamserver_media_available{library}`, `streamserver_videos`, `streamserver_music_folders`,
  `streamserver_transcodes_active{kind}`, `streamserver_transcodes_max{kind}`, `streamserver_cache_bytes`,
  `streamserver_event_loop_lag_max_seconds` (самое долгое «подвисание» Node с прошлого опроса; при > 2 с — предупреждение
  в журнале: обычно это перегрузка Pi или своп).

«ffmpeg не найден» ставится, только если бинарника действительно нет; если ffmpeg просто долго отвечал
(Pi занят сразу после старта), проверка повторяется каждые 10 минут без ложной тревоги.

## Доступ извне через EC2

Пример конфигурации nginx — `deploy/nginx-ec2.conf`: домен → WireGuard-IP mediaserver, порт 8090,
с выключенной буферизацией. HTTPS обязателен (certbot), иначе пароль идёт открытым текстом.

⚠️ Весь трафик пойдёт через EC2, а исходящий трафик AWS платный сверх бесплатного лимита —
фильм на 4 ГБ ≈ 4 ГБ трафика. Альтернатива без этих затрат: подключать телефон/ноутбук к
WireGuard и открывать `http://<wg-ip-mediaserver>:8090` напрямую.

Скорость: для 1080p нужен upload домашнего интернета ~8–15 Мбит/с на один поток.

## Разработка

```bash
npm start          # API на :8090 (нужны MEDIA_ROOT и CINEMA_PASSWORD в окружении)
npm run dev:web    # UI с hot reload на :5173, /api проксируется на :8090
```

## API

| Метод | Путь | |
|---|---|---|
| POST | `/api/login` | `{ "password": "..." }` → cookie |
| POST | `/api/logout` | |
| GET | `/api/videos` | список (`?refresh=1` — пересканировать) |
| GET | `/api/stream/:id` | видео, поддерживает `Range` |
| GET | `/api/subtitle/:id?offset=` | внешние субтитры в WebVTT |
| GET | `/api/music/tree` | папки с аудио (`?refresh=1`) |
| GET | `/api/music/folder?path=` | треки папки с тегами, CUE разбит на треки |
| GET | `/api/music/folder-deep?path=` | треки папки и всех подпапок (до 5000) |
| GET | `/api/music/stream/:id?q=orig\|eco` | трек (оригинал или кешированное перекодирование), `Range` |
| GET | `/api/music/prepare/:id?q=` | подготовить трек заранее |
| GET | `/api/music/cover?path=&s=` | обложка JPEG |
| GET / POST | `/api/playlists` | список / создать `{name, tracks?}` |
| GET / PUT / DELETE | `/api/playlists/:id` | плейлист с треками (`missing` у пропавших) / изменить `{name?, tracks?}` / удалить |
| GET | `/api/probe/:id` | кодеки, дорожки, длительность, режим |
| GET | `/health` | без логина: `ok` / `degraded` (503) |
| GET | `/metrics` | без логина, только из LAN: метрики Prometheus |
| GET | `/api/status` | занятые/доступные слоты перекодирования |
| GET | `/api/seekpoint/:id?t=&audio=` | точка старта потока (ключевой кадр) |
| GET | `/api/transcode/:id?start=&ss=&audio=` | поток через ffmpeg (fMP4) |
| GET | `/api/subtitle-embedded/:id/:n?offset=` | встроенные субтитры в WebVTT |

`id` — base64url относительного пути; выход за пределы `MEDIA_ROOT` блокируется.

## Идеи для развития

- Превью-кадры: `ffmpeg -ss 60 -i файл -frames:v 1 -vf scale=320:-1 thumb.jpg` в фоне, с кешем.
- Постеры и описания из TMDB.
- HLS вместо fMP4 — для iPhone/Safari.
